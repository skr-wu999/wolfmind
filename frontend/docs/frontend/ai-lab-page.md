# AI 实验室前端原型

入口 `/lab`，大厅底部有“AI 实验室”链接。布局按用户参考图实现：左侧 Agent 配置、中间营火工作台、右侧批量测试/模型比较/结果概览、底部进度与导出栏。复用村庄场景、导航、游戏桌、像素头像、图标、木框和详情弹窗。没有新增依赖，未修改后端和共享 API / WebSocket 契约。

## 配置与批次

配置包括名称、经典九人角色、性格、策略、示例模型、温度、提示词、记忆与工具选项。支持新建、编辑、保存、配置库选择。保存到当前标签页的 `sessionStorage`；存储不可用时保留内存数据，损坏的存储不会替换内置配置。关闭会话后不保证保留。最多 30 份配置。

本地表单校验名称 1–24 字、提示词 1–800 字、温度 0–1、样例次数 1–50、有效整数种子范围、并发上限 1–8，至少选择一份已保存配置。报错保留输入并聚焦首个错误字段；温度或并发错误会打开高级设置。保存和提交成功聚焦结果标题。

批次固定使用提交时的已保存配置与选项快照。未保存的编辑不进入批次；运行期间允许准备下一批次的配置，但拦截重复提交和清空。按 `docs/frontend/page-design.md` §4.8 使用**显式刷新**，没有进度轮询或自动运行计时器。本地适配器每次刷新推进 `round(4 × speed)` 组样例（最少一组），达到总数后完成；演示速度不会执行或加速真实模型。刷新失败保留进度，比较失败保留旧结果并提供重试。

## 数据来源

`features/lab/types.ts` 是前端展示类型，`LabAdapter` 是可替换的本地适配边界，不定义新的公开 REST DTO。`stores/lab.ts` 管理加载、草稿、已保存配置选择、提交、手动刷新、比较、导出与清空，并阻止旧请求或卸载后的响应覆盖当前状态。拒绝访问时隐藏可提交区域；正式权限必须由服务端验证。

四个模型档案均为手工界面样例，不调用 LLM、不保存 API 密钥，也不执行领域规则。每组记录包含各配置的独立预置胜出阵营；比较中的胜局数按对应配置阵营统计，胜率为胜局数 / 已完成组数。报告与 JSON 可核对这些记录；相同模型更改提示词、温度、策略或记忆不会据此推算真实性能。质量、耗时（秒）和稳定性是预置数值，规则 Bot 的发言质量缺失保留 `null`。零完成批次所有指标显示“暂无数据”。首次加载有 20 组预置比较数据，清空后不再回填。

模型比较支持胜率、发言质量、决策耗时、稳定性排序与角色筛选；耗时升序，其余降序，缺失值排最后。概览同步显示当前筛选下的最高胜率、最高发言质量、最短耗时和最高稳定性。语义表格给出完整数值，手机允许表格区域横向滚动。

工作台复用独立的**已结束九人对局样例**，并非当前批次产生的实时比赛。支持身份标签切换、只读席位详情、阶段跳转、日志/摘要/系统事件、玩家过滤、详细级别与自动跟随日志。不会展示晚于播放游标的记录，也不会声称访问模型私有思维过程。可以从报告进入该独立样例的回放和分析。

报告中的批次记录 `gameId` 全部为 `null`，没有伪造真实对局链接；未来仅在服务端返回已授权 `gameId` 后提供相应分析入口。JSON 导出包含数据来源、批次快照、逐组配置结果与比较。清空需要弹窗确认，仅删除当前内存实验记录，保留 Agent 配置。

## 正式接入待办（TBD）

根据 `docs/backend/api-spec.md` §8：配置读取/保存映射 `GET/POST /lab/agent-configs`；批次创建映射 `POST /lab/batches`；显式查询映射 `GET /lab/batches/{batchId}`；比较映射 `GET /lab/comparisons`。服务端负责配置授权、模型可用性、并发限制、合法规则、队列、执行与真实统计；同样经过应用服务和 `Game` 聚合。客户端不直接调用模型或改写权威游戏状态。

角色组合、种子、演示速度与模型参数到正式 DTO 的映射，以及质量/稳定性指标定义和授权报告链接，需与后端协调确认。当前只读经典九人配置为 3 狼人、3 村民、1 预言家、1 女巫、1 猎人；没有新增规则变体。配置的工具勾选不构成真实权限授权，外部联网入口未开放。
