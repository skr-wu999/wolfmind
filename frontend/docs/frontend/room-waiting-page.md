# 房间等待页本地原型

实现日期：2026-10-11。按用户提供的等待页参考图替换原座位预览，路由仍为 `/rooms/:roomId`，内部名称为 `room-waiting`。本文只定义本地前端展示，不修改共享协议或游戏规则。

## 布局与组件

桌面左侧木框分为篝火座位布局和玩家列表，右侧上下排列房间信息与游戏设置。保留参考图的大厅标题位置、树形标识、挂灯、屋顶狼、纸张颜色、橙色准备按钮和底部村庄控制。

复用 `VillageScene`、`VillageHeader`、`VillageHud`、`PixelDialog`、`PixelIcon`、音效组合函数和已有木框样式。屋顶狼抽出为 `VillageRoofWolf`，大厅和等待页共用。真人头像调用原 Canvas `person` 绘制，通过新增 `drawPortrait` 接口显示；动物头像和篝火使用代码 SVG。头像仅是昵称形象，不代表狼人杀角色或阵营。

`RoomSeatBoard` 展示九个座位与公开状态，点击座位和玩家列表均打开同一详情弹窗。宽屏保持围坐布局，窄屏改为双列卡片，玩家列表和右侧面板依次往下排列。座位号始终可见；Tab、Enter 可打开详情，方向键按座位号移动焦点并循环，弹窗支持 Escape 和焦点恢复。

参考图的十二人数字仅作布局参考，实际容量采用批准的经典九人局。参考图 AI 未准备的示例与 `ddd-design.md` INV-R2 冲突，实际 AI 自动准备。

## 展示模型

扩展 `features/lobby/types.ts` 的本地模型，未定义服务端 DTO：

| 字段 | 本地含义 / 不变量 |
| --- | --- |
| `seats[9]` | 九个有唯一序号的座位 |
| `seatNo` | 1..9 |
| `name` | 昵称；空位为 null |
| `controller` | HUMAN、AI 或空位 null；不是秘密身份 |
| `ready` | 真人默认未准备，准备操作置 true；AI 始终 true，空位 false |
| `isMe` / `mySeatNo` | 当前本地会话占用的唯一座位 |
| `avatar` | green/blue/red/wolf/owl/fox 的展示形象 |
| `ownerSeatNo` | 房主所在的真人座位；无人房间可为 null |

准备人数、AI 数量和玩家数量从座位快照计算，列表摘要不携带详细座位或房主信息。初始雾隐村房间含四个玩家和三个 AI，加入后为 8 / 9。

原 `wolfmind.demo.rooms.v1` 会话数据保持同一键。旧数据缺少的控制方式、头像、准备和房主字段在读取时迁移，保留当前成员与座位；已知脚本村民名称替换为本地展示昵称。损坏、非法座位和人数不一致的数据报错，不静默覆盖。存储读写不可用后持续使用内存，避免后续读取旧存储覆盖刚完成的操作。

## 操作与状态

| 操作 | 本地适配器 | 结果 / 边界 |
| --- | --- | --- |
| 查看空位并入座 | `takeSeat(roomId, seatNo)` | 占用指定空位；已占、重复坐另一座和已开始拒绝 |
| 准备 | `ready(roomId)` | 必须是已入座成员；幂等标记本人 true，刷新后保留 |
| 房主添加 AI | `setAi(roomId, seatNo, true)` | 只能用于空位 / AI 座位；自动准备，人数同步增加 |
| 房主移出 AI | `setAi(roomId, seatNo, false)` | 回到空位；不能修改真人座位 |
| 复制房间号 | Clipboard API | 显示复制结果；失败提示手动复制 |
| 返回大厅 | `leave(roomId)` 后导航 | 释放自己的座位与准备状态；本地房主离开时移交首个真人座位，没有真人时房主为 null |
| 手动刷新 / 窗口获焦 | `get(roomId)` | 重新读取快照；无轮询、无房间 WebSocket |

每次准备、入座或 AI 操作完成后重新查询快照，座位卡、玩家列表、人数及准备摘要统一更新。请求期间禁用重复提交；失败保留反馈并重新读取快照。加载时显示九个不可操作的空位骨架；无效房间提供重试和返回大厅。版本标记避免旧房间请求覆盖新路由，卸载时清理焦点监听与共享场景资源。

准备只能标记完成，暂不提供取消准备，因为现有 POST ready 契约没有取消语义。非房主不显示开局按钮，房主开局按钮始终禁用并说明当前条件和未接入服务；即使九人全部准备，也不会在前端模拟真实开局。正式阶段时长和进阶配置只读，等待服务端定义。底部昼夜控制只改变村庄演示，不是比赛计时器。
