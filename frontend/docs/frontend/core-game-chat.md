# 核心游戏页：游戏桌、群聊与阶段操作栏

2026-10-13。依据用户提供的[共享设计说明](https://chatgpt.com/s/t_6acd1ca436f481918c857daf783a1a6a)，重构 `/games/:gameId` 的展示结构。保留现有像素村庄、游戏桌、头像、木框、角色技能、行动二次确认、真实 REST / WebSocket 适配器及登录要求。

## 页面与组件

- `GamePage.vue`：统一房间、天数、阶段与倒计时；桌面约 62% 游戏桌 / 38% 群聊，最大宽度 1520px。手机提供游戏桌与群聊切换，组件保持挂载，草稿与选择不因切换丢失。
- `GameChatPanel.vue`：公开发言、系统消息、流式预览、回合筛选、展开式发言顺序及内联输入。其他玩家靠左，本人靠右，系统消息居中。只在讨论/遗言阶段显示本轮进度，夜间不显示过去的发言顺序。
- `GameActionDock.vue`：复用 `RoleSkillBar` 的身份与木框，把投票、查验、用药和猎人目标操作移到游戏桌下方。桌上选择与展开式目标列表同步；技能资源、目标、弃票/放弃资格来自已有 `permissions`。
- `GameTable.vue`：增加可选的当前回合标签；没有流式发言时显示“当前回合”，避免声称玩家已经开口。其他使用该组件的页面维持默认标签。
- 公开日志使用现有 `PixelDialog` 展开为右侧抽屉；角色记录、个人结果、玩家资料与确认继续复用该弹窗的焦点管理。

聊天列表有独立滚动范围，消息增加不会撑高桌面页面。接近底部时跟随新消息；向上阅读或筛选旧回合时保留当前位置并显示新消息按钮。增量更新复用同一个 `speechId`，提交后的消息取代预览，不新增重复气泡或重复未读计数。发送成功后聚焦最新记录；失败、重连、面板切换保留草稿。路由和本地演示场景重置仍按原有流程处理。

## 数据与权限边界

没有更改 REST / WebSocket 契约。`GameMessage.order` 与 `GameRecord.order/round` 是可选的前端排序信息；真实适配器从已授权回放事件的 `seq`、`round` 映射。旧展示数据没有这些字段仍可读取，本地样例只添加展示排序序号。没有新增服务端字段、游戏规则或模型调用。

`mapGame.ts` 把已经收到的 `PHASE_CHANGED`（目标阶段取 `payload.to`）、公开发言回合、死亡公告、投票结算及终局事件转成系统提示，顺序按事件版本排列。只读取当前视图版本以内的事件；技能结果仍在原个人投影中，不把夜间死亡过程、其他职业结果或私有事件复制到公共聊天。发言顺序、目标与胜负继续使用权威视图和已提交事实。

频道出现条件是已有授权记录或明确权限。角色名称本身不创建私人/狼人频道。个人记录仅在个人频道渲染；狼人记录仅在狼人频道渲染。频道数据消失后返回公共讨论。是否允许发送由已有 `SPEAK` / `WOLF_CHAT` 权限、连接、截止时间与忙碌状态控制。遗言授权优先于存活状态；观战和终局隐藏提交控件。

**狼人夜聊（2026-10-13 接入后端）：**动作名由 `WOLF_CHAT_PREVIEW` 改为 `WOLF_CHAT`，与 api-spec.md §5.3 一致。服务端只在 `NIGHT_WOLF` 给存活狼人下发 `WOLF_CHAT` 权限（`remaining` 为本夜剩余条数，上限 20），提名之后仍保留到阶段结束。发送走 `POST /actions`（`{ content }`，1..500 字）；消息来自已授权回放中的 `WOLF_CHAT_SENT`（`WOLF` 可见），`mapGame.ts` 映射为 `wolfMessages`，`WOLF_CHAT_SENT` 已登记在 `VIEW_MUTATING` 里，用于刷新消息与剩余条数。非狼人的回放与推送不含该事件。
