# WolfMind 第一版收尾计划（HTTP 单机内测版）

日期：2026-10-14。

**状态：待所有者审阅的提案。** 按所有者指出的原收尾清单修订：个人资料、管理员运维入口、短期记忆与策略经验的生成/持久化、实际提示词模板选择，均纳入本轮；不再默认推迟到下一版。本文件只制定范围与验收标准，不表示功能已实现、已部署或已通过验收。

## 1. 交付目标与 HTTP 条件

目标：补齐原收尾清单中的功能缺口，并交付单台服务器上的可用内测版。范围包括现有经典九人对局、历史、回放、分析、实验室，以及个人资料、受保护的运维入口、可生成并恢复的 Agent 记忆、实际生效的提示词模板选择。完成这些仍不代表多实例、高可用等全部远期规划完成。

继续使用 Java、Vue、Nginx、Redis、SQLite 和 Docker Compose。浏览器通过同一站点访问页面、`/api/` 与 `/ws`；服务器入口使用 `http://服务器地址:端口`，WebSocket 使用 `ws://`。本轮不要求安装证书，也不强制跳转到服务器尚未提供的 HTTPS。

HTTP/WS 不提供传输加密，登录凭据、会话令牌和私密对局信息可能被网络中间人读取或修改。HTTP 下的交付定位为内网或限定访问的内测；IP 白名单只能减少暴露面，不能替代传输加密。使用独立测试账号和不复用的密码。若计划向任意公网用户开放，应另列 HTTPS 入口方案后再按公开服务验收。

仅 Nginx 的站点端口对外；Redis 和后端端口留在容器网络中。模型 API 密钥只保存在服务器配置，不进入前端产物、日志或交付报告。

执行前待填写：服务器操作系统、CPU/内存/磁盘、当前访问方式（内网/公网）、允许访问的人员或 IP、现有数据是否需保留、维护时间窗、模型验收费用上限、站点端口。填写信息不改变游戏规则或架构。

## 3. 执行顺序与验收

### 第一步：确定范围，整理遗留问题

逐项核对 `docs/review/summary.md`、TASKS、README、现有代码和测试，把当前状态整理为：已修复、本轮待实现、本轮待验收、范围外、尚待确认。每项记录证据，不凭旧审计内容判断现状。

交付阻断项包括：无法开局或终局、非法行动被接受、身份或夜间秘密泄露、重连状态错误、已提交事件损坏、归档或统计重复、资源随终局持续累积、部署配置不生效、数据无法按约定恢复。

核对新增功能的已批准契约。现有 API 已列出用户查询和管理员运维接口，但管理员身份与授权、记忆更新/恢复的细节仍需具体设计。`promptTemplateId` 当前契约明确只作比对标签，本轮改为实际模板选择属于契约变化，须先提交可审阅的修订，不直接按旧字段含义实现新行为。新接口字段或权限未定义的部分列为 TBD。

**验收：** 形成一份当前问题清单，阻断项必须修复并有回归证据；延期事项明确列出，不宣称全部产品规划已完成。

### 第二步：补齐个人资料与管理员运维入口

个人资料：按现有 `GET /users/{userId}` 和 `GET /users/me/stats` 契约完成查询和页面，接入真实账号、已结束对局和实际统计，不使用模拟数据。仅展示契约允许公开的资料，本人统计按当前会话读取；本轮不隐含新增修改密码、上传头像等未列入清单的功能。

管理员运维：先明确管理员如何由服务器侧配置或初始化授予、身份如何保存、接口如何鉴权；普通用户不能通过客户端字段或自行注册获得管理员身份。接通已有恢复和 DLQ 查询/重试接口，并提供最小可操作入口，不扩展成完整用户管理后台。

恢复和重试通过应用服务执行，复用版本校验、幂等和权限检查；记录操作人、对象和结果。坏事件不能通过重试入口绕过解码或领域校验。HTTP 条件下，管理员入口再限定管理网络或来源 IP；不只靠隐藏按钮控制权限。

**验收：** 资料与统计来自真实数据；未登录和普通用户访问运维接口均被拒绝；管理员可查看测试环境故障并执行受控恢复/重试；重复操作不重复产生事实或统计。字段、错误码、管理员身份和审计契约同步到文档。

### 第三步：接通 Agent 记忆生成、保存与恢复

复用 MemoryPort 与既有 SQLite `agent_memory` 设计，不把决策轨迹当作已实现的记忆。短期记忆从该座位获授权的已提交事件生成 EPISODE/FACT，保留来源事件、局/座位、可见范围和版本水位，按稳定键幂等更新。

按 MemoryUpdater 的批准职责接入可靠消费，明确与 cg-agent 调度的先后关系及确认条件；记忆失败不能使整局永久停止。记忆水位落后时，从获授权的事实构造当前上下文，后台补做记忆；记录进度，不因重启重复生成相同条目。具体接线与事务边界在实施前形成契约。

长期策略经验从可观察的策略结果和终局复盘生成 STRATEGY/REFLECTION；只保存结构化经验或简短总结，不索取模型私有思维链。跨局条目按配置所属账号、Agent 配置和角色隔离，去掉上一局玩家身份、座位映射及不应跨局传播的秘密。

上下文构建真正读取记忆，`memoryMode` 对读取/生成行为有明确作用；设定条数、长度、保留期和更新时间，避免无限增长。若复盘需要模型调用，单独定义有限预算、超时与重试，终局结果和归档不等待复盘；不能未经说明占用下一回合额度。优先从确定性事实和已有决策摘要生成可验证内容。

**验收：** 相同事件重复投递只产生一份记忆；进程重启后同座位记忆可恢复；下一局只读取属于该账号/配置且允许跨局的经验；模型上下文中可验证实际引用了记忆；无跨座位、跨账号或公开发言泄密。失败、积压与限额可观察，补做不重新提交行动。

### 第四步：让实验室提示词模板选择实际生效

建立服务器端受控模板注册表，先支持少量有明确差异的模板；实验室发送真实模板 ID，PromptBuilder 根据配置选择模板。模板不得删除工具授权、信息隔离或游戏合法性约束。

记录实际模板 ID、版本及模型输入版本，便于比较和复现；已有 `default` 保持当前默认行为。现有 `custom` 标签的迁移方案和未知 ID 的拒绝行为须在契约修订中明确。本轮目标是实际选择模板，不隐含开放任意文本编辑或外部模板加载。

**验收：** 相同可见局势、不同模板 ID 得到对应的实际模型输入；房间/实验室配置传递完整；历史记录能识别当时模板版本；未知模板有明确错误，权限隔离仍通过回归。

### 第五步：准备可复现的 HTTP 部署与回退

核对 `deploy/docker-compose.yml`、Nginx、环境变量与数据卷。验证前端同源 REST 和 WS，避免浏览器指向 localhost、空 WebSocket 地址或不存在的 HTTPS 入口。

保存现有配置、镜像标识和数据备份；将新产物与构建时间、源码版本或源码包校验值、配置项清单关联。先在隔离环境演练，再在维护窗口部署。环境变量更新通过重新创建后端容器生效；只 restart 不算完成配置更新。

确认默认 Redis 存储、事件驱动调度、LangGraph4j、Function Calling、四组消费启用；根据服务器容量确定并发上限和模型费用上限，不直接把默认值当作服务器容量。

验证依赖正常时健康接口返回 200，必需依赖异常时返回 503。后端不可用时能被现有探测发现；Nginx `/healthz` 仅证明前端容器可用，不能替代后端依赖检查。

记录回退步骤。应用镜像回退不能默认撤销数据库变化；若旧版本与新数据不兼容，使用维护窗口的配套备份恢复，并明确会失去备份之后的数据。图引擎异常仍按既有规则兜底；配置切换顺序引擎仅重启后生效，不在同一回合重新执行。

**验收：** 从干净环境按文档构建并启动成功；HTTP 页面、REST、WS 均使用服务器地址；外部无法直连 Redis；能够演练恢复上一可用版本。

### 第六步：完成正常业务和真实浏览器验收

先用固定模型回答或规则机器人执行自动化；测试使用独立数据环境，不清空业务 Redis 或 SQLite。

本版至少完成以下发布用例，各局保存对局 ID、结果和验收记录：

| 场景 | 最低用例 | 验收重点 |
| --- | --- | --- |
| AI 对局 | 3 局不同种子 | 从开局到终局，发言/投票/技能合法，事件可重放 |
| 真人与 AI 混合 | 2 局不同真人座位 | 多账号同步、主动提交、超时补做、真人接管 |
| 真人多人 | 1 局九个独立账号 | 独立会话和座位授权，拒绝冒充或跨座位行动；可由自动化账号驱动 |
| 历史与回放 | 上述已结束对局 | 终局结果一致、事件有序、重启后可查 |
| 分析与实验室 | 1 个小批次和已归档对局 | 账号隔离、配置有效、批次完成、统计不重复；未提供的曲线显示暂无数据 |
| 新增收尾功能 | 资料、运维、记忆恢复、模板选择各一套端到端流程 | 后端能力与浏览器操作一致，权限有效，重启后数据和配置仍可用 |

逐项检查注册/登录/退出、房间创建加入准备开局、页面刷新、遗言与技能操作、重复点击、过期命令、非法目标、自定义规则及禁止弃权。检查村民、狼队、特殊角色、观战者和另一账号的数据权限；回放在终局前遵守现有揭示策略。

浏览器至少覆盖 Chromium 与 Firefox 的关键流程，再检查手机宽度下的按钮、发言区、投票和错误提示；WebKit 如未执行，报告明确记为未验收。多账号自动化不能替代所有实际浏览器交互检查。

在上述流程通过后，执行少量真实模型验收：建议 1 局 AI 对局、1 局混合对局，预先确定费用上限。检查工具调用、计划与发言、降级比例、延迟和 token 用量；不因对局结束就宣称机器人策略质量已达到某个水平。真实模型偶发失败仍须合法兜底并完成对局。

**验收：** 所有必验流程通过，日志无密钥与越权秘密；实际浏览器操作与服务器状态一致；付费验收记录与自动化记录分开。

### 第七步：演练异常和恢复

在隔离环境测试后端中途重启、Redis 暂时不可达、SQLite 暂时写入失败、模型超时或错误、玩家断线后重连、重复消息、坏事件隔离。

检查四组各自重试或接管：已提交事件不被重复提交，统计不重复计数，故障恢复后未完成任务可补做；一个组的处理失败不把另一个组的成功误判成全局成功。坏事件按现有契约隔离并报告，不为“恢复”而跳过领域事实。

确认未完整归档的事件不设置清理 TTL；完整归档后删除测试环境中的该局 Redis 记录，SQLite 可恢复终局与历史且不重新调用模型。进行中、尚未归档的对局不能假定可以从 SQLite 恢复。

断线重连以授权快照和遗漏事件同步；重复消息不重复呈现已提交动作，公开发言预览与最终提交分开。

**验收：** 每个故障用例记录预期与实际结果，故障解除后在测试设定的超时/接管窗口内恢复或明确隔离；无重复行动、重复统计和权限泄露。Redis AOF everysec 的崩溃丢失窗口仍按现有持久化约定说明，不承诺零丢失。

### 第八步：补齐备份与基本运维

第一版优先提供简单、可演练的配套备份：在维护窗口暂停后端写入，正常停止 Redis，完整备份 SQLite 数据卷和 Redis 数据卷，再恢复服务；备份过程会产生短暂不可用，需记录实测时长。不得在运行中的数据库上随意复制单个 `.db` 或单个 AOF 文件并称为有效备份。

如要在线备份，SQLite 使用 Backup API 等一致性备份方法，Redis 使用其支持的快照/持久化备份流程；额外核对跨存储恢复边界，不能默认两个独立时间点能恢复到完全相同进度。

建议每天一次备份，至少保留最近 7 份，并保存一份到服务器之外；实际周期、容量、保留期和可接受恢复点（RPO）在服务器信息确认后定稿。备份文件限制访问并记录校验值。恢复时间（RTO）以演练实测为准。

必须在独立空环境恢复一次：账号可登录、历史可查、SQLite 完整性检查通过、Redis 数据可加载、选定归档对局可重放；维护窗口前的活动局按备份水位恢复并可继续或按明确策略结束。只确认备份文件存在不算验收。

提供启动、停止、升级、回退、备份、恢复和排障说明；通过现有健康与指标接口定期检查依赖、内存、磁盘、消费组阻塞、待归档对局、模型降级和预算。检测到异常至少留下日志和人工可查结果，本版不新增监控平台。

**验收：** 自动备份入口与日志可用、一次真实恢复成功、恢复点与恢复时长有记录、运维说明可按步骤执行。

### 第九步：测容量，形成交付结论

先单局，再 2 局并发，资源允许时再增加；先固定模型排查应用处理能力，再用有费用限制的小规模真实模型测延迟。记录 CPU、内存、磁盘、队列、消费积压、对局完成率和模型等待时间。

结束多局后检查 Agent、轨迹缓存与成本账本回到配置边界，不能随已结束对局持续无界增长。稳定观察至少 2 小时，确认没有持续积压或卡局。并发测试上限根据服务器配置调整，不提前承诺支持多少在线玩家。

交付 `docs/ops/release-acceptance.md`，每项标注通过/失败/未执行及证据；记录镜像/源码标识、环境配置、测试对局、资源数据、备份恢复和已知限制。同步 README、TASKS 与审计的当前状态，历史记录保留。

**验收：** 个人资料、管理员运维入口、记忆生成与跨重启恢复、实际模板选择全部有实现与验收证据；无未解决的交付阻断项；必验流程和恢复演练通过；给出实测并发上限、费用上限及 HTTP 内测范围。满足后称为“第一版 HTTP 单机内测版完成”，不称为全产品规划或公开生产版全部完成。

## 4. 本版延期事项

原清单中的功能缺口和 AI 增强已纳入本轮；仅下列不在原清单中的增强或当前环境限制继续留待后续：

1. 胜率曲线与信念模型口径、任意自定义提示词编辑。
2. 多后端实例、跨实例广播、高可用和更大规模性能优化。
3. 面向任意公网用户的 HTTPS/WSS 入口与相应发布验收（按当前仅 HTTP 的服务器条件暂缓）。

若所有者要求其中某项属于第一版，则在执行前加入交付范围与验收，不隐含扩展本计划。
