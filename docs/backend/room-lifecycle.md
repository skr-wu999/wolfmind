# 房间退出与终局生命周期

2026-10-14，所有者批准。房间仍为一房一局：WAITING → RUNNING → CLOSED；结算、回放与历史属于 Game，不因房间关闭删除。

## 命令与事实

- 等待房 `POST /rooms/{roomId}/leave`：本人座位释放，房主移交首个剩余真人；最后一个真人离开，提交 ROOM_CLOSED(reason=NO_HUMANS)。
- 运行房同一退出命令：在 Room 流提交 PLAYER_CONTROLLER_CHANGED，将该座位标记为退出后的 AI 控制者，保留房间座位身份与位置；最后一个真人离开后关闭。事件保存退出意图，失败/重启后可补做。
- `POST /games/{gameId}/leave`：会话身份与该 Game 关联 Room 中的原真人身份匹配；禁止观战者或陌生账号退出其他人的座位。响应为 RoomView，服务端已确认关闭的房间返回幂等成功。需 Idempotency-Key。
- 运行房退出后，应用用例将 Game 的对应控制者换为 AI，角色、存活状态及已提交行动保留；发布 PLAYER_CONTROLLER_CHANGED。AI refId 为规范玩家 ID。
- 全部真人退出且 Game 尚在运行：提交 GAME_ABORTED(reason=NO_HUMANS)，不计正常胜负；不再创建新接管 Agent。
- NO_HUMANS/ROOM_CLOSED 中止的统计仍保存历史、存活状态和模型成本，games_played=0、games_won=0，不进入胜率分母。
- GAME_FINISHED/GAME_ABORTED 后提交对应房间的 ROOM_CLOSED，默认大厅列表排除 CLOSED。历史 Game 事件保留。

跨 Room/Game 聚合不伪装成同一事务：先可靠保存 Room 退出意图，再锁定 Game 更新；每步仅在提交成功后发布。
命令失败时客户端不跳转，后台按已提交意图补做；重复退出和终局通知不重复提交事件。房主移交在事件 apply 中计算，重放结果与在线处理一致。

## 在线与宽限

在线定义为同账号至少一个已认证连接订阅该等待房或关联 Game。页面导航、连接断开、离开成员关系分别处理。
多标签页按账号合并；观战者不能为其他成员维持在线。WS 心跳负责清理死连接。

默认断线宽限 `wolfmind.room.disconnect-grace-ms=120000`；补漏周期 `wolfmind.room.reconcile-ms=30000`。
首次检查不在线成员时开始宽限，重连立即取消计时；进程重启后重新给予宽限，避免启动期间误踢。
宽限到期通过同一退出用例处理。最后一个真人离开后关闭普通房间，尚在运行的对局中止。
AI 竞技场/实验室独立创建 Game，不属于 Room 索引，普通房间扫描不会中止它们。

内存模式订阅已提交终局通知；Redis 模式由 cg-projection 在终局归档后处理对应房间关闭，失败保留待重试消息。
定时扫描修复漏通知、跨聚合中途失败及历史遗留 RUNNING 房间，每房异常单独记录，不中断其余检查。

## 界面与增量字段

对局页面保留结算，参与者显示“退出房间并返回大厅”；进行中先提示 AI 接管/最后真人退出会中止，再确认。
退出成功后解除订阅并跳转大厅；新对局加载时清空座位选择。失败保留页面并显示错误。观战者仅返回大厅。
大厅列表摘要增加 humanCount、aiCount（机器人计入 aiCount），显示占用座位及真人/AI 数量；默认不显示 CLOSED。
在线大厅每 15 秒更新列表；隐藏标签页、建房输入中或操作处理中不主动刷新，回到可见页面立即更新。
非 STALLED 的中止不展示“连续多轮无人出局”；NO_HUMANS 显示“所有真人已离开，本局中止，不计胜负”。

验收覆盖：两个真人退出、房主移交/重放、已投票后接管、陌生账号/观战拒绝、多标签/重连/宽限、最后真人中止、
终局通知重复/归档重试、重启补漏、默认大厅过滤、AI 专用 Game 不受影响、前端退出失败不导航。
