# Phase 4 观战披露政策提案

状态：**已批准选项 A（2026-10-12）**。项目所有者明确选择“进行中仅公开记录，赛后完整记录”。共享契约按此政策更新；不新增消息字段、不改变游戏规则。

## 已解决的冲突

`page-design.md` §4.5 要求进行中的 AI 对局提供上帝视角，展示 PUBLIC / WOLF / PRIVATE / JUDGE 全部可见事件。
当前 `AGENTS.md` §8 / §14 要求隔离角色秘密，并禁止在对局结束前通过观战数据暴露私有角色信息。
现有真实只读适配器使用服务端授权视图和回放；不能为了符合旧页面文案放宽服务端过滤。

## 选项 A：进行中公开记录，赛后完整记录（建议）

- 进行中观战显示公开身份状态、公开发言、已公开死亡、阶段与计时，不显示未披露角色或私有夜间行动。
- 页面明确标记“公开观战”，不提供上帝视角开关，不请求客户端声明的身份或 visibility。
- 参与者使用本人对局页；观战接口和订阅按服务端身份及政策裁剪数据。
- 对局结束后的披露由服务端已有赛后政策决定，页面只展示收到的授权字段。
- 需同步 `page-design.md` §4.5 与相关观战契约的上帝视角说明，不新增消息字段。

## 选项 B：仅全 AI 对局提供授权上帝视角

- 服务端确认所有座位均为 AI，并校验观战授权后，才允许进行中角色和私有事件披露。
- 含真人对局继续按公开记录展示；参与者无法通过观战订阅获得其他角色私有信息。
- 订阅语义须由服务端确认，客户端不能通过开关或查询参数提升权限。
- 需要所有者明确批准 `AGENTS.md` 中隐藏信息限制的这一例外，并同步 API / WebSocket / 页面契约。
- 不应只改前端文案或将现有公开订阅冒充为上帝视角。

## 确认后两种方案共有的开发范围

1. 接入 `SUBSCRIBE`、授权初次快照、GAME_EVENT、断线与 RESUME；使用 REST 授权视图刷新，前端不重建规则。
2. 去重与水位按已有协议处理，停止页面订阅后丢弃旧响应及回调，退出终局直播后提供回放入口。
3. 用真实模式文案替换本地示例标签、固定 AI 人数和固定总天数；未知的决策摘要保持空状态。
4. 验证匿名、参与者、其他账号、含真人/全 AI、进行中/赛后、重连和重复事件的授权矩阵。
5. 验证至少一局持续接收阶段与发言直到终局，页面与授权 REST 版本一致，非法数据没有被浏览器接收。

选项 B 保留为未采用的备选。模型流式推理、AI 决策分析与实验室不属于这项政策决策的附带授权。
